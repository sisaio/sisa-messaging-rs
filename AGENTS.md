# Codex team orchestration

- Prefix every shell command with `rtk`, including each command in a chain; see `RTK.md`.
- Treat `docs/README.md` and the documents it indexes as normative. Do not silently change a
  documented guarantee, ownership boundary, schema invariant, or non-goal.
- The primary agent is the delivery lead and requirements steward. It writes only orchestration or
  documentation artifacts and routes bounded issue packets (`docs/agent-workflow.md` section 4)
  through the section 5 workflow; agents get the packet, never transcripts or raw logs.
- Use the configured GPT-6 Sol/Luna roles; GPT-6 Astra is not a project role or escalation.
  Balanced is Sol at medium effort for the writer, fast is Luna at extra-high effort for delivery
  work, and flagship Sol at high effort stays gated to architecture, final review, or another named
  risk; model capability, not effort, is the quality lever.
- Ask `architect` only for an unanswered design decision or high-risk schema, transaction,
  locking, fencing, concurrency, cancellation, compatibility, or cross-crate change.
- `backend_developer` exclusively owns Rust, runtime SQL, tests, Cargo manifests, and lockfiles;
  `release_engineer` owns only assigned CI/CD, Atlas migration mechanics and versioned SQL, release
  artifacts, and publication preparation. Never run overlapping writers; send fixes to the owning
  writer with `followup_task` and state a reason for any fresh writer spawn.
- Require independent `reviewer` review after every material Rust, SQL, migration, test,
  manifest/dependency, or CI/release change, and G2's fresh final review for normative documents
  and agent configuration. Approval binds to the (merge base, reviewed tree hash) pair the final
  reviewer records, so an authorized commit of the identical tree needs no new review. Do not give
  `architect` or `reviewer` write access; verify their handoffs changed no files.
- `.agents/` is the source of truth; `.codex/` and `.claude/` files are generated by
  `.agents/sync.sh`, whose `--check` also enforces the G6 size caps.
- Run broad validation once per stable head; other roles consume it.
- GitHub Issues and the linked Project are authoritative: one approved issue, one task, one linked
  branch, normally one PR, with approval per issue moving it from `Todo` to `In Progress`. Branch
  names, Conventional Commits with `Refs #`, `Closes #` in the PR body, and the 10/25 path targets
  with 20/99 hard limits are enforced by the `prek` hooks and CI; section 7 of the workflow document
  is the text. Never use `--no-verify`, never enable auto-merge or merge, and never commit, push, or
  open a PR unless the user asks.

# Portable rules (full text: `docs/agent-workflow.md` section 5)

- **G1 Review-round cap.** One initial review, at most one batched fix round, one fresh final
  review. Only a blocker/high final finding opens one more round; a G3-qualifying medium/low final
  finding is fixed and primary-verified with both tree hashes recorded, others are deferred to a
  linked issue. Never run consecutive reviewers without an edit between them.
- **G2 Editorial class.** Comments, docstrings, typos, formatting, and non-normative Markdown need
  no agent review; normative docs and agent configuration get one fresh final review only.
- **G3 Small fix.** At most five paths, no new files, no runtime-code, schema, or migration change:
  skip the focused review and go straight to the fresh final review.
- **G4 Bounded reads.** Read diff hunks and named sections, never whole files, documents, or
  generated folders; narrow commands before they exceed the output limit. A named concurrency,
  security, or migration risk may justify more and must be reported.
- **G5 Hook output.** Pipe `git push` and `prek run` through `tail -n 40` under `set -o pipefail`;
  the explicit check run, not hook output, is the evidence.
- **G6 Size caps.** `docs/agent-workflow.md` at most 8 KB, `AGENTS.md` at most 6 KB, each role
  source at most 3 KB, enforced by `.agents/sync.sh --check`; a new rule displaces text and points
  at a named section rather than restating one.
- **G7 One writer.** One writer owns a PR unless another writer's exclusive domain is touched.
- **G8 No polling.** Await external state with one blocking call (`wait_agent` at the maximum
  timeout, `gh pr checks <n> --watch --fail-fast`, `gh run watch <id> --exit-status`) piped through
  `tail` under `set -o pipefail`; never poll with `list_agents`, `wait`, repeated `gh`, or shell.
- **G9 Filtered reads.** Every reading `gh`/`gh api` call selects fields with `--json`/`--jq`; no
  `--comments`, no unfiltered `gh api`; drop bot authors unless dispositioning their findings. Web
  search stays disabled; design questions go to the architect gate or the user.

# Repository-specific routing (Rust/Cargo, SQLx offline, Atlas)

- **L1.** Cargo manifests, lockfiles, and their test/code adaptations belong to
  `backend_developer`; `release_engineer` is spawned only for CI, versioned migrations, `atlas.sum`,
  release, or publication files (P3).
- **L2/P1.** CI's `cargo sqlx prepare --check` is the proof for `.sqlx/**`; `rg` ignores it,
  reviewers exclude it from diffs, and its regeneration is exempt from the 10/25 targets but not
  the 20/99 hard limits.
- **P2.** Database and migration fixes keep the focused re-review (`docs/agent-team.md` section 6).

# Security and performance lenses

- Never commit or expose secrets, payloads, raw header values, credentials, or connection URLs; no
  `unwrap`/`expect` on database, broker, wire, or other untrusted input paths.
- Keep SQL parameterized and bounded; never block the Tokio runtime, spawn unbounded work, or hold
  a lock or database transaction across broker or network I/O.
- Justify every new dependency, keep features minimal, run `cargo deny check` when dependency state
  changes, and preserve `#![forbid(unsafe_code)]` across library crates.
- A changed hot path names its benchmark evidence; a changed query or index needs a representative
  PostgreSQL 18 `EXPLAIN (ANALYZE, BUFFERS, WAL, FORMAT JSON)` plan test.
